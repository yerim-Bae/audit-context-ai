# 감사맥락AI

낯선 산업에 감사 투입되기 전, **무엇을 물어볼지 정하는 도구**입니다.

감사인이 처음 만나는 산업에서 먼저 막히는 것은 근거가 없어서가 아니라 말이 통하지 않아서입니다. 담당자가 "탑재 끝나고 진수 대기"라고 할 때 못 알아들으면 그 자리에서 얻을 것을 놓칩니다. 이 도구는 **산업 구조를 먼저 익히고, 그 위에 회사 공시를 얹어 산업 일반론과 이 회사가 어디서 갈라지는지**를 봅니다.

그 갈라지는 지점이 곧 물어볼 것입니다.

## 이 도구가 하는 일과 하지 않는 일

| 하는 일 | 하지 않는 일 |
|---|---|
| 산업의 거래 구조를 카드로 읽기 | 회계처리 적정성 판단이나 감사 의견 |
| 회사 공시(DART)를 받아 원문 위치까지 남기기 | 근거 없이 빈칸을 채우기 |
| 산업 일반론과 회사 사실을 나란히 놓고 차이 보기 | 산업 일반론을 회사 사실로 올리기 |
| 근거 없는 항목을 **물어볼 질문**으로 바꾸기 | 사람이 검토하지 않은 문장을 화면에 내보내기 |

오른쪽 열이 이 저장소의 실제 내용을 더 많이 규정합니다. 규칙은 문서가 아니라 **검사와 데이터 구조**로 강제됩니다 — 아래 "규칙을 코드로 강제하는 방법" 참조.

> **실제 감사자료 반입 금지**
> 이 저장소에는 접근제어도 암호화도 없습니다. **감사조서·은행조회서·계약서 등 비공개 자료를 넣지 마십시오.**
> 들어 있는 회사 자료는 전부 DART 전자공시의 **공개 원문**뿐입니다([ADR 0007](docs/decisions/0007-allow-dart-ingestion.md)).

## 열어보기

`실행하기.bat` 을 더블클릭하거나:

```bash
npm start
```

검은 창에 나오는 주소를 브라우저에서 엽니다. 다른 프로그램이 5173을 쓰고 있으면 자동으로 다음 포트로 비켜 갑니다.

### 화면 구성

| 파일 | 내용 |
|---|---|
| `index.html` | 첫 화면 — 산업을 고릅니다 |
| `deck-shipbuilding.html` · `deck-nuclear.html` | 산업 카드덱 |
| `overlay-hd-hyundai-mipo.html` | 회사 오버레이 — 산업 표준과 다른 점 |
| `travel-bsp.html` | 가상 여행사 BSP 거래 지도 |
| `hanatour.html` | 하나투어 공시로 확인된 것과 안 된 것 |
| `candidates.html` | 근거 후보 검토(승인 전) |

### 15분에 훑는 순서

1. 첫 화면에서 **조선업**을 고르고, 회사명에 `에이치디현대미포`, 위치 `조선사`, 필드 `매출·채권` 을 넣습니다.
2. 카드 몇 장을 읽습니다. 각 카드의 **축 배지**(`◇ 산업 일반` / `◈ 확인 필요` / `? 미확인`)를 봅니다. 색이 아니라 글자로 구분됩니다.
3. 위쪽 **`이 회사 차이표 →`** 를 누릅니다. 여기부터 회사 층입니다.
4. `CO-02` 차이표에서 왼쪽(산업 일반론)과 오른쪽(이 회사 공시)을 비교합니다.
5. **`근거 보기`** 를 누르면 사업보고서 원문 섹션이 인용문과 함께 열립니다.
6. **`! 산업과 다름`** 행을 봅니다 — 산업 카드는 공사기간을 2~3년이라 하는데 이 회사 주석은 "일반적으로 1년"입니다.
7. **`? 미확인`** 5행이 `CO-03` 에 질문으로 올라와 있고, 질문에서 원래 행으로 되돌아가집니다.

## 규칙을 코드로 강제하는 방법

이 저장소의 설계 대부분은 "사람이 실수해도 규칙이 깨지지 않게" 하는 데 쓰였습니다. 세 가지 예입니다.

**차이표 행의 상태는 적는 값이 아니라 계산값입니다.** `overlay.json` 에 `status` 필드가 아예 없습니다. 근거가 없으면 `UNVERIFIED`, 그때 질문이 없으면 로더가 막습니다. **근거를 붙이지 않고 "회사 확인"이라고 적을 방법이 없습니다**([ADR 0011](docs/decisions/0011-company-overlay-on-pack-deck.md)).

**축은 도메인 열거값이고 트랙은 팩 데이터입니다.** 축(`INDUSTRY`/`MIXED`/`UNVERIFIED`)은 `Scope`·`AssertionStatus` 로 되돌아가 "카드는 `FACT` 가 될 수 없다"를 강제하므로 팩이 늘릴 수 없습니다. 트랙은 목차 제목일 뿐이라 산업마다 다릅니다([ADR 0012](docs/decisions/0012-tracks-are-pack-data.md)).

**신뢰 도메인이 다르면 디렉터리를 나눕니다.** `seed/` 는 스냅샷·해시·인용문 대조가 데이터 수준에 걸려 있고, `packs/` 는 그 규칙을 하나도 만족하지 못합니다. 같은 폴더에 두면 규칙을 느슨하게 하는 수밖에 없어서 나눴습니다([ADR 0009](docs/decisions/0009-add-industry-packs-and-onboarding-deck.md)).

## 명령

```bash
npm start              # 빌드 + 로컬 서버
npm run build          # 모든 화면 만들기 (dist/)
npm test               # 검사 114건
npm run typecheck      # tsc --noEmit
npm run format:check   # prettier --check
```

DART 를 부르는 것은 아래 셋뿐이며 **로컬에서만 실행합니다.** 배포된 화면은 미리 구운 HTML이라 인증키가 필요 없습니다.

```bash
npm run dart:check                                          # 인증키 확인
npm run dart:find -- "대양전기공업"                            # 회사명 → 고유번호
npm run dart:fetch -- 00111193 --out daeyang --terms shipbuilding   # 원문 한 건 수집
```

회사가 밸류체인 어디쯤인지 **제안**받으려면:

```bash
npm run company:suggest -- "대양전기공업" --pack shipbuilding --fetch
```

사업보고서의 사업 서술만 읽고 근거 문장과 함께 제안합니다. **확정하지 않습니다** — 낱말이 몇 개 걸렸는지만 세고 문장의 뜻은 읽지 않으므로, 사람이 근거를 보고 골라야 합니다.

### 인증키 설정 (새 회사를 추가할 때만)

[DART 오픈API](https://opendart.fss.or.kr/)에서 키를 받아 `.env` 에 넣습니다. `.env` 는 git에 올라가지 않습니다.

```bash
cp .env.example .env
```

## 아직 없는 것

- **AI 자동 추출** — 모든 Claim은 사람이 원문을 보고 승인했습니다
- **실시간 DART 조회** — 정적 화면이라 브라우저가 DART를 부르지 않습니다([ADR 0006](docs/decisions/0006-static-render-instead-of-nextjs.md))
- **데이터베이스** — 시드 JSON을 직접 읽습니다([ADR 0001](docs/decisions/0001-defer-database.md))
- **브라우저 e2e 테스트** — 화면 검사는 생성된 HTML 문자열을 봅니다
- **해운업 팩** — 조선업 카드덱의 밸류체인 위치에 해운사가 있지만 아직 비어 있습니다

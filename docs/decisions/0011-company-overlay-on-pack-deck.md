# ADR 0011 — 카드덱 위에 회사 오버레이를 올린다 (범위 변경)

- 날짜: 2026-08-11
- 상태: 승인됨

## 뒤집는 결정

[ADR 0009](0009-add-industry-packs-and-onboarding-deck.md)의 재검토 조건에 이렇게 적혀 있습니다.

> 회사 자료로 `COMPANY` 카드를 만들자는 요구가 나올 때 — 카드덱이 `seed/`의 규칙 아래로 들어와야 합니다

그 요구가 나왔고, **이 ADR이 그 조건을 발동시킵니다.** `docs/onboarding-deck-design.md` §10의 "회사 오버레이 카드 — 만들지 않습니다"도 함께 뒤집습니다. 다만 조건부입니다 — 오버레이는 카드덱의 규칙이 아니라 `seed/`의 규칙 아래에서 만듭니다.

## 왜 필요한가

카드덱만으로는 "업계는 대체로 이렇다"에서 멈춥니다. 감사인이 실제로 필요한 것은 "이 회사는 실제로 이렇다"이고, 둘의 차이가 곧 물어볼 것입니다. 산업팩 26장을 다 읽어도 담당 회사에 대해 알게 되는 것은 0건입니다.

한편 [ADR 0007](0007-allow-dart-ingestion.md)로 DART 원문 수집이 이미 열려 있고, 사업보고서는 `docs/source-policy.md` 기준 **A등급**이며 `can_support_scope`에 `COMPANY`가 들어 있습니다. 즉 회사 카드는 근거만 붙이면 `FACT`가 될 수 있습니다. 재료는 이미 있고, 연결만 없었습니다.

## 비대칭이 핵심이다 — 두 층은 화면에서 달라 보여야 한다

| | 산업 카드 (`packs/`) | 회사 카드 (오버레이) |
|---|---|---|
| 출처 | 산업 강의 — C등급, 단일 화자 | DART 사업보고서 — A등급 |
| `scope` | `INDUSTRY` | `COMPANY` |
| 가능한 상태 | `INFERENCE`·`UNVERIFIED` (`FACT` 불가) | `FACT` 가능 — 단, 직접 근거가 있을 때만 |
| 근거 클릭 | 없음 (팩 출처 고지만) | 원문 섹션이 열려야 함 |
| 읽는 문장 | "업계는 대체로 이렇다" | "이 회사는 실제로 이렇다" |

이 차이가 화면에서 **눈에 띄게** 보이지 않으면 오버레이를 붙인 의미가 없습니다. 카드가 매끄럽게 읽히는 것이 위험이라는 ADR 0009의 경고가 여기서 더 커집니다 — 회사 이름이 붙는 순간 독자는 전부를 사실로 읽습니다.

## 규칙 — 오버레이는 seed/ 의 규칙을 그대로 받는다

1. 회사 카드의 모든 `FACT` 문장은 그 회사 공시의 `EvidenceSpan`을 최소 1개 갖습니다 (도메인 규칙 2).
2. 산업 카드는 회사 문장의 근거가 될 수 없습니다 (도메인 규칙 4). 차이표의 "산업 표준" 열은 근거가 아니라 **비교 기준**이며 화면에서 그렇게 표시합니다.
3. 근거가 없는 행은 조용히 비우지 않고 `UNVERIFIED`로 남겨 질문으로 전환합니다 (도메인 규칙 8).
4. 회사 데이터는 `packs/` 가 아니라 `seed/<company>/` 아래에 둡니다. 팩은 여전히 학습 표면이고, 오버레이는 근거 자산입니다.
5. 오버레이 카드는 `cards.json` 에 넣지 않습니다. 팩 무결성 검사 D1(“`FACT` 0건”)과 정면으로 충돌하기 때문입니다.

## 이번에 만드는 것 — 3장만

파이프라인이 도는지 보는 것이 목적이므로 전부 만들지 않습니다.

| ID | 제목 | 하는 일 |
|---|---|---|
| `CO-01` | 이 회사는 무엇을 파는가 | 사업 부문·수익 구성. 근거 있는 것만 `FACT` |
| `CO-02` | 산업 표준과 다른 점 | 산업 카드의 주장 × 이 회사의 실제, 행마다 근거 또는 `UNVERIFIED` |
| `CO-03` | 이 회사에 물어볼 것 | `CO-02`의 `UNVERIFIED` 행에서 자동으로 올라온 질문 |

## 끝났다고 보는 조건

한 사람이 브라우저에서 끊김 없이 다음을 할 수 있으면 뼈대가 선 것입니다.

회사 선택 → 산업 카드 열람 → 차이표로 이동 → 한 행의 근거를 눌러 DART 원문 섹션 열기 → 근거 없는 행이 `UNVERIFIED`로 보임 → 그 행이 `CO-03`에 질문으로 올라와 있음 → 질문에서 원래 주장으로 역추적

## 허용하지 않음

- 회사 카드에서 회계 결론·감사 의견 제시 (도메인 규칙 10)
- 근거 없이 산업 일반론을 회사 문장으로 바꿔 쓰기 — 이것이 이 ADR이 막으려는 단 하나의 실패입니다
- 오버레이 문장의 모델 자동 생성 후 무검토 반영 (ADR 0009와 같은 선)

## 재검토 조건

- 회사가 2곳을 넘어 차이표의 산업 기준을 팩 카드에서 자동으로 끌어와야 할 때
- 오버레이가 `AuditRisk`·`RequestItem` 까지 확장되어 여행업 한정 경계에 닿을 때 — 그때는 `CLAUDE.md` MVP 경계를 다시 봐야 합니다

# ADR 0009 — 산업팩과 온보딩 카드덱을 추가한다 (범위 변경)

- 날짜: 2026-08-10
- 상태: 승인됨 (2026-08-11)

## 뒤집는 결정

`CLAUDE.md`의 MVP 경계는 "Domain: travel agencies"이며 "Do not add other industries ... unless the user explicitly changes scope"라고 못박습니다. `docs/product-design.md` §12도 "다중 산업"을 제외 항목으로 둡니다. [ADR 0008](0008-allow-all-listed-companies.md)이 BM 대시보드에 한해 이를 풀었고, **이 ADR이 학습 표면에 한해 다시 풉니다.** 감사 연결(거래 지도·위험·요청자료·질문)의 여행업 한정은 유지합니다.

## 왜 넓히는가

감사인이 배정받는 회사는 대개 여행업이 아닙니다. 낯선 산업에서 먼저 막히는 것은 근거의 부족이 아니라 말이 통하지 않는 것입니다. 담당자가 "탑재 끝나고 진수 대기"라고 말할 때 못 알아들으면 그 자리에서 얻을 것을 놓칩니다.

이 공백은 `seed/`로 메울 수 없습니다. 산업 관행에는 스냅샷과 해시를 붙일 공식 원문이 대체로 없고, 있어도 인터뷰 전날 읽을 형태가 아닙니다. 필요한 것은 근거 자산이 아니라 **학습 표면**입니다.

## seed/ 와 packs/ 의 차이

| | `seed/travel-bsp` | `packs/<industry>` |
|---|---|---|
| 성격 | 근거 원문이 붙은 Claim 자산 | 2차자료 기반 학습 표면 |
| 출처 | IATA 공식 문서, DART 공시 | 산업 강의 스크립트 (단일 유형) |
| 최소 단위 | `Claim` + `EvidenceSpan` | 카드 |
| 가능한 상태 | `FACT` 포함 | `FACT` 불가 ([ADR 0010](0010-lecture-source-grade-and-limits.md)) |
| 검사 | 신뢰성 검사 T1~T17 | 카드 무결성 검사 D1~D11 |

**둘을 섞지 않습니다.** 카드를 근거로 Claim을 만들지 않고, Claim 문장을 카드에 복사하지 않으며, 로더·검사·화면·빌드 명령을 분리합니다.

## 왜 별도 디렉터리인가

`seed/`에는 스냅샷·해시·직접 근거·인용문 대조 규칙이 데이터 수준에 걸려 있습니다(`docs/source-policy.md` §8). 강의에서 뽑은 서술은 이 규칙을 하나도 만족하지 못합니다. 같은 디렉터리에 넣으면 규칙을 느슨하게 하거나 예외를 뚫는 수밖에 없고, 둘 다 `seed/`를 오염시킵니다. **디렉터리를 나누면 규칙을 나눌 수 있습니다.**

```text
packs/<industry>/
  pack.json    산업, 출처 목록, 시점 범위
  sources/     무손실 소스노트
  knowledge/   참조 라이브러리
  cards.json   카드덱
```

## 정적 렌더를 유지한다

[ADR 0006](0006-static-render-instead-of-nextjs.md)의 방식을 그대로 씁니다. `npm run deck:build`가 `cards.json`을 읽어 산업당 정적 HTML 한 장을 만듭니다. 런타임 의존성 0개, 브라우저 JS는 카드 이동과 로컬 키워드 검색만 담당합니다. 본문이 전부 생성된 HTML 안에 있으므로 축 배지 누락·출처 고지 누락·분량 초과를 브라우저 없이 검사할 수 있습니다.

모델을 호출해 카드를 즉석 생성하지 않습니다. **사람이 검토한 것만 나갑니다.** 근거는 `docs/onboarding-deck-design.md` §7.

## 허용하지 않음

- 산업별 `AuditRisk`·`RequestItem`·`InterviewQuestion` 시드 생성 (ADR 0008이 그은 선과 같습니다)
- 회사 사실 서술 — 카드는 산업 일반만 다룹니다
- 팩 자동 생성 — 스크립트→소스노트→마스터→카드의 각 단계를 사람이 검토합니다

## 결과

- 얻는 것: 감사인이 낯선 산업에 들어가기 전 읽을 것이 생기고, 산업이 늘어도 `seed/`의 규칙과 검사는 그대로입니다
- 비용: 자산 종류가 둘이 되어 문서·검사·명령이 갈라집니다
- 위험: **카드는 잘 읽히기 때문에 신뢰돼 보입니다.** Claim보다 근거가 약한데 화면은 더 매끄럽습니다. 이 비대칭이 가장 큰 위험이며 ADR 0010이 그 대응입니다

## 재검토 조건

- 팩이 3종을 넘을 때 — 산업 간 공통 개념의 중복 처리를 정해야 합니다(`docs/product-design.md` §16)
- 회사 자료로 `COMPANY` 카드를 만들자는 요구가 나올 때 — 카드덱이 `seed/`의 규칙 아래로 들어와야 합니다

# ADR 0007 — DART 공시 수집을 허용한다 (범위 변경)

- 날짜: 2026-08-05
- 상태: 승인됨 (사용자 선택)

## 뒤집는 결정

`docs/product-design.md` §12는 "DART 자동 연동"을 **제외 항목**으로 정하고 있었습니다. 이 ADR이 그 결정을 조건부로 뒤집습니다.

## 왜 뒤집는가

지금 저장소에는 **회사 특정 사실이 0건**입니다. 회사 범위 Claim 9건이 전부 추정 또는 미확인입니다. 가상 회사이므로 근거가 존재할 수 없기 때문입니다([ADR 0004](0004-no-fabricated-company-documents.md)).

DART 공시는 **회사 특정 A급 근거**입니다. 사업보고서 주석에는 사용제한예금의 금액과 사유가 실제로 기재됩니다. 즉 이 연동은 제품의 가장 큰 공백을 정확히 그 자리에서 메웁니다.

## 무엇을 허용하고 무엇을 허용하지 않는가

### 허용

- 회사명으로 회사를 찾고, 지정한 공시 원문을 **한 건씩** 가져오기
- 가져온 원문을 다른 출처와 **똑같이** 취급: 불변 스냅샷 저장, SHA-256 해시, 페이지·문단 위치 보존
- 원문에서 검색어가 나오는 위치를 찾아 **근거 후보** 목록 만들기 (`src/ingest/candidates.ts`)
- 사람이 원문을 보고 확정한 인용문만 Evidence Span으로 등록

### 허용하지 않음

- **자동 크롤링**: 사용자가 지정한 회사·공시만 가져옵니다. 목록을 훑어 자동 수집하지 않습니다.
- **후보 → 사실 자동 승격**: 후보는 아무 상태도 갖지 않습니다. 검색 결과는 근거가 아닙니다.
- **확정적 분석**: 실제 회사명이 화면에 나오더라도 회계처리 적정성이나 감사의견을 제시하지 않습니다. 위험은 계속 "가능성 … 확인 필요"로만 씁니다.
- **기존 DART 프로젝트 코드 복사**: 필요한 기능만 어댑터로 연결합니다(설계안 §3).

## 이 변경이 깨뜨리는 기존 불변식

테스트 T17은 "어떤 출처도 `COMPANY` 범위를 지지할 수 없다"를 강제합니다. DART 출처가 들어오면 이 규칙은 **가상 사례에 한정**되도록 좁혀야 합니다. 실제 회사 사례에서는 회사 특정 근거가 존재하는 것이 정상입니다.

가상 여행사 사례(CASE-001)의 보장은 그대로 유지합니다. 실제 회사는 **별도 사례**로 만들고, 두 사례의 데이터를 섞지 않습니다.

## 새로 생기는 위험

- **실명이 화면에 붙습니다.** 사람은 회사 이름이 있으면 화면 내용을 결론으로 읽습니다. 상태 표시와 "확인 필요" 문구가 더 중요해집니다.
- **공시에 없는 것이 많습니다.** 질권자, 담보 산정 기준, BSP 송금 주기는 사업보고서에 대체로 나오지 않습니다. 이때 빈칸을 메우지 않고 미확인으로 남기는 것이 이 도구의 역할입니다.
- **API 키가 외부 자격증명입니다.** 저장소에 넣지 않고 `.env`로 관리하며, `.gitignore`에 이미 포함되어 있습니다.

## 아직 하지 않은 것

이 ADR 시점에 만들어진 것은 **API 키 없이 검증 가능한 부분**뿐입니다.

- `src/ingest/candidates.ts` — 결정적(deterministic) 근거 후보 찾기, 검사 8건
- DART 연결 자체는 API 키 확보 후 구현합니다

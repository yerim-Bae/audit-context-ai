# ADR 0001 — 첫 화면까지는 데이터베이스를 도입하지 않는다

- 날짜: 2026-08-05
- 상태: 승인됨 (사용자 승인)

## 맥락

`CLAUDE.md`와 `docs/product-design.md`는 PostgreSQL + Drizzle ORM + S3 호환 저장소 + Python 문서 작업자를 권장합니다. 그러나 첫 세로 흐름은 미리 큐레이션한 시드 데이터를 **읽어서 보여주기만** 합니다. 쓰기도, 동시성도, 검색량도 없습니다.

동시에 `시작하기.md` 4단계의 합격 기준은 "README 안내만 따라 로컬 화면이 열리는가"입니다. 사용자는 개발자가 아니며, Docker Compose로 데이터베이스와 오브젝트 스토리지를 띄우는 절차는 이 기준과 정면으로 충돌합니다.

## 결정

첫 실행 화면까지는 **JSON 시드 파일을 직접 읽습니다.** PostgreSQL, 오브젝트 스토리지, 작업 큐, Python 작업자를 도입하지 않습니다.

`docs/product-design.md` §7의 테이블 설계는 폐기하지 않고, 시드 파일의 구조와 `src/domain`의 타입으로 그대로 옮겨 둡니다.

## 재도입 조건

다음 중 하나가 발생하면 이 결정을 다시 검토하고 새 ADR을 씁니다.

- 사용자가 PDF를 업로드해 원문 스냅샷이 저장소 밖에서 늘어나기 시작할 때
- Claim 검토 결과(승인·반려)를 저장해야 할 때
- 사례가 둘 이상이 되어 데이터가 사례별로 분리되어야 할 때

## 결과

- 얻는 것: 설치 없이 실행. 고장 지점 감소. 첫 화면까지의 시간 단축
- 비용: 이후 데이터 접근 계층을 한 번 교체해야 함. 화면 코드는 영향받지 않도록 로더를 `src/seed/load.ts` 한 곳에 모아 둠
- 위험: 시드가 커지면 파일 전체를 매번 읽는 방식이 느려짐. 현재 규모(Claim 20건)에서는 문제되지 않음

# 산업팩 작성 가이드

산업팩 하나를 만드는 전체 절차서. 조선업 1종을 실제로 만들면서 확인된 값을 기준선으로 쓴다.

| | |
|---|---|
| 대상 산업 | 반도체, 이차전지, 원전, 헬스케어, 우주항공, AI, 피지컬AI, 자율주행, 풍력 (9종) |
| 완성 사례 | 조선업 1종 — `packs/shipbuilding/` |
| 프롬프트 | `prompts/pack/01~04` |
| 현황표 | `packs/README.md` |

## 1. 산업팩이란 무엇인가

감사 투입 전 온보딩 도구의 4층 구조 중 **첫 층**이다.

```
① 산업팩        이 산업은 어떻게 돌아가는가          ← 재사용 (산업당 1회 구축)
      ↓ 좁힘
② 회사 오버레이  이 회사는 그 안에서 무엇을 하는가     ← 회사당 1회
      ↓ 구체화
③ 거래 지도      계약부터 현금·회계처리까지            ← 회사당, 거래유형별
      ↓ 필드로 절단
④ 필드 렌즈      내 계정에서 무엇을 봐야 하는가        ← 담당자당
```

이 가이드는 ①만 다룬다. ②~④는 회사 자료가 있어야 만들어진다.

**산업팩 층에는 회사 사실이 한 줄도 들어가지 않는다.** 전부 `[산업 일반]` 축으로 태깅된다. 산업 자료는 특정 회사가 그 거래를 실제로 한다는 사실을 증명하지 못한다(`docs/source-policy.md` §3). 산업 일반론을 회사 프로세스로 착각하는 것이 이 도구가 막아야 할 가장 위험한 실패다.

## 2. 파이프라인

```
raw 원자료 ──P1──▶ 소스노트 (편당 1개)
                      │
                      ├──P2──▶ 통합 마스터 (마스터 1 + 분책 7)
                                    │
                                    ├──P4──▶ field-matrix.json   ← 먼저
                                    │              │
                                    └──P3──▶ cards.json (24~26장)
```

**P4가 P3보다 먼저다.** 매트릭스가 카드에서 무엇을 깊게 쓸지 결정한다. 카드를 먼저 쓰면 분량 배분의 근거가 없어 산업 백과사전이 된다.

| 단계 | 프롬프트 | 입력 | 출력 | 실행 횟수 |
|---|---|---|---|---|
| P1 | `prompts/pack/01-source-note.md` | 원자료 1건 | 소스노트 1개 | 소스 수만큼 (6~8회) |
| P2 | `prompts/pack/02-merge-pack.md` | 소스노트 전부 | 마스터 1 + 분책 7 | 섹션별 6회 + 인터뷰질문지 1회 + 마스터 조립 1회 = 8회 |
| P4 | `prompts/pack/04-field-matrix.md` | 마스터 + 분책 | `field-matrix.json` | 1회 |
| P3 | `prompts/pack/03-cards.md` | 마스터 + 분책 + 매트릭스 | `cards.json` | 1회 (분할 실행 시 2~3회) |

## 3. 원자료 투입 순서

**순서를 뒤집으면 공시를 읽어도 문장이 안 읽힌다.**

| 순위 | 소스 | 잘 나오는 것 | 안 나오는 것 |
|---|---|---|---|
| **1** | 유튜브 산업강의 | ① 산업 구조, ③ 비즈니스 구조, **용어**, **관행** | 정확한 수치, 최신성, ④ 거래구조 세부 |
| 2 | 증권사 산업리포트 | ① 밸류체인, 지표 정의, 수치 | ④ 거래구조, 회계 |
| 3 | 증권사 기업리포트 | ② 사업구성, ③ 실적 동인 | 산업 조망, ④ |
| 4 | 사업보고서 (사업의 개요) | ② ③ ④ 일부 | 산업 맥락 |
| **5** | **사업보고서 주석 + KAM** | **④ 거래구조와 회계처리** | 산업 맥락 |
| 최종 | 담당자 인터뷰 | ④의 마지막 빈칸 | — |

> 강의로 언어를 배우고 → 리포트로 구조와 숫자를 채우고 → 공시로 거래구조를 확정하고 → 인터뷰로 빈칸을 메운다.

**강의가 1순위인 이유**는 용어와 관행 때문이다. 리포트는 독자가 산업을 안다고 전제하고 쓰여서, 모르는 상태로 읽으면 문장이 안 들어온다. 강의는 모르는 사람에게 말하므로 비유와 관행이 나온다. **④ 거래구조는 강의에서 절대 완성되지 않는다** — 그것을 아는 것이 강의 단계의 목적이다.

### 4·5순위의 위치

사업보고서는 특정 회사의 자료다. 산업팩 층에 그 내용을 넣으면 회사 사실이 산업 일반론으로 섞여 들어간다. **사업보고서에서 산업팩으로 가져올 수 있는 것은 "이 산업의 회사들이 공통적으로 쓰는 계정과 회계정책의 유형"까지**이고, 특정 회사의 비율·조건·금액은 회사 오버레이(②층)로 간다. 이 경계를 지키기 어려우면 산업팩은 1~3순위 소스로만 만들고 4~5순위는 ②층에서 처음 쓰는 편이 안전하다.

조선업 팩은 1순위 소스만으로 만들어졌다. 그래서 `(확인)` 등급 항목이 0건이다.

## 4. 산업당 최소 구성

| 소스 | 최소 | 이유 |
|---|---|---|
| 산업강의 | 2~3편 (기초 / 밸류체인 / 최근 이슈) | 용어와 관행의 뼈대 |
| 증권사 산업리포트 | **2편 이상, 서로 다른 증권사** | 관점 대조가 되어야 무엇이 통설이고 무엇이 개인 견해인지 갈린다 |
| 사업보고서 | 1건 (사업의 개요 + 주석 + KAM) | ④가 여기서 완성된다 |

**소스 유형이 1종이면 확신도가 올라가지 않는다.** 같은 화자가 두 번 말한 것은 교차확인이 아니다. 조선업 팩은 8편 전부 동일 화자의 유튜브 강의라 사실상 전량 `(전언)` 등급이고, 같은 유형을 더 넣어도 ④ 거래구조는 한 건도 열리지 않는다.

**시점 폭도 최소 구성의 일부다.** 같은 달에 몰린 소스만 있으면 무엇이 변한 값이고 무엇이 고정된 구조인지 구분할 수 없다. 조선업은 2024-03~04 클러스터와 2026-06 단 1편으로 나뉘어, 그 사이 2년 3개월이 비어 있다.

## 5. 소요 감각

조선업 1종 기준. **실행 횟수와 산출 분량**으로 적는다 (실제 소요 시간은 실행 환경에 따라 달라진다).

| 단계 | 실행 | 1회당 산출 | 누적 |
|---|---|---|---|
| P1 소스노트 | 8회 | 70~87KB | 612KB |
| P2 분책 통합 | 6회 | 50~120KB | 약 570KB |
| P2 인터뷰질문지 | 1회 | 57KB | |
| P2 마스터 조립 | 1회 | 13KB | |
| P4 매트릭스 | 1회 | JSON 1개 | |
| P3 카드 | 1~3회 | 카드 8~13장 | 89KB / 26장 |
| **합계** | **18~20회** | | 마스터 7권 + JSON 2개 |

**P1이 전체 작업량의 절반 이상이다.** 그리고 여기서 손실이 나면 뒤 단계가 전부 무의미해지므로 줄일 수 없는 구간이다.

**P3는 한 번에 26장이 안 나온다.** 조선업에서는 카드를 3덩이(`cards_a/b/c`)로 나눠 생성한 뒤 합쳤다. 나눌 때는 트랙 단위로 자르고, **링크 그래프 검증은 반드시 합친 뒤 전체에 대해** 한다. 나눠 만들면 끊긴 링크와 고아 카드가 생긴다.

### 병목과 대처

| 병목 | 증상 | 대처 |
|---|---|---|
| P1 축약 | 소스노트가 30KB 이하 | 청크를 잘게 나눠 재실행. 길이 제한 없음을 명시 |
| P2 통합 누락 | 612KB를 한 번에 통합 시도 → 뒤쪽 소실 | **섹션별 6회로 분할.** 프롬프트 02 §실행 순서 |
| 헤딩 불일치 | 섹션 분할이 편마다 다른 내용을 집음 | 2편째에 `grep -n "^## "` 대조 |
| P3 장수 미달 | 카드가 15장에서 끝남 | 트랙별로 나눠 생성 후 병합 |

## 6. 품질 게이트

각 단계는 아래를 통과해야 다음으로 간다. **통과하지 못하면 재작업이지 보정이 아니다.**

### G1 — 소스노트 (P1 이후, 편마다)

- [ ] `✅ 커버리지` 블록 존재
- [ ] **미반영 0**
- [ ] **숫자 전수 대조 통과** — 수치를 전부 나열해 원문과 1:1로 맞춘다. 교정한 수치는 원문 병기
- [ ] 고유명사 전수 대조 통과 — 기업·기관·인명 전부 나열
- [ ] 리서처 주석이 전부 `(리서처 주석)`으로 표시됨
- [ ] ④ 거래구조 (빈칸)이 1건 이상 — 0건이면 추측으로 채웠을 가능성
- [ ] `## ` 헤딩이 같은 산업의 다른 노트와 일치

### G2 — 통합 마스터 (P2 이후)

- [ ] 원자 합계가 소스노트들의 합과 일치
- [ ] **소실 0** (본문 반영 + 부록 보존 = 총 원자)
- [ ] 상충 목록이 비어 있지 않음
- [ ] 시점 클러스터가 식별되고, 클러스터 간 차이가 상충이 아니라 변화로 처리됨
- [ ] 최신 소스 미언급 항목이 삭제되지 않고 표시만 됨
- [ ] 마스터 §한계 절이 채워짐 — 소스 유형 편중, 시점 공백, `(확인)` 비율

### G3 — 매트릭스 (P4 이후)

- [ ] 개념 12~20개
- [ ] `positions × fields` 전 칸이 채워짐
- [ ] `조건부`에 전부 `condition` 있음
- [ ] 위치 간 뒤집힘 3건 이상
- [ ] 필드마다 `필수` 3개 이상
- [ ] `thin: true`가 있으면 **P3로 넘어가기 전에 소스 보강**

### G4 — 카드 (P3 이후)

`prompts/pack/03-cards.md` §7의 검증 스크립트를 돌린다.

- [ ] 24~26장, id 유일, 끊긴 링크 0, 유입 0 카드 0
- [ ] 본문 800~1,400자, 표 규격 (선언된 예외만)
- [ ] `audit` 전 카드 존재
- [ ] 허용 태그 외 0, `class`·`style` 0, 이모지 0
- [ ] **필수 카드 유형 15가지 전부 커버**
- [ ] **수치 전수 대조** — 카드의 모든 숫자가 마스터에 실재 (기계로 못 잡는다. 사람이 본다)
- [ ] 회사 사실을 단정한 문장 0

### G5 — 팩 (전체)

- [ ] `pack.json`의 `known_limits`가 채워짐. **한계가 없는 팩은 없다**
- [ ] `sources` 목록의 시점·유형·등급이 전부 기재됨
- [ ] `packs/README.md` 현황표 갱신

## 7. 조선업 실측 기준선

새 산업의 산출물이 이 범위를 크게 벗어나면 원인을 확인한다.

| 지표 | 조선업 값 | 해석 |
|---|---|---|
| 원자료 | 자동자막 8편, 약 280KB¹ | 30분 강의 1편당 약 35KB |
| 소스노트 | **612KB** (74·80·87·71·72·86·76·70KB) | 원자료의 약 2.2배. **줄어들면 축약된 것이다** |
| 정보 원자 | **1,684개** (187·212·228·192·230·205·251·179) | 강의 1편당 179~251개 |
| 미반영 | **0** | 8편 전부 |
| 숫자 전수 대조 | **99.8%**¹ | 교정 2건·판독불가 1건·화자 번복 1건은 원문 병기로 처리 |
| 통합 마스터 | 마스터 13KB + 분책 7권 약 570KB | |
| 용어 | 416개 (+ 인터뷰 즉응 30선) | |
| 빈칸 | 63건 (그중 ④ 거래구조 32건) | **강의만으로 만든 팩은 ④가 절반 이상 빈다** |
| 상충·함정 | 8건 | 마스터 §3에 별도 표로 |
| 카드 | **26장**, 89KB | 산업기초 6 · 비즈니스 3 · 거래구조 9 · 기자재 2 · 용어 1 · 필드 4 · 마무리 1 |
| 카드 본문 | 796~1,066자 | 규격 800~1,400의 하단에 몰려 있다 |
| `(확인)` 등급 | **0건** | 소스가 1순위 유형뿐이라 당연한 결과 |

¹ 원자료 자동자막 원문과 대조율은 팩 제작 시 보고된 값이며, 원문 스크립트는 이 저장소에 보관되어 있지 않다. 소스노트 612KB와 원자 1,684개는 `packs/shipbuilding/knowledge/`에서 재확인된다.

### 이 기준선에서 읽을 것

- **소스노트가 원자료보다 커지는 것이 정상이다.** 구조화·확신도 태깅·빈칸 표시가 붙기 때문이다. 원자료보다 작아지면 요약한 것이고, 그 팩은 못 쓴다.
- **④ 거래구조 빈칸 32건은 실패가 아니라 성과다.** 강의로 열리지 않는 것이 무엇인지 정확히 아는 상태가 됐다는 뜻이고, 그것이 미확인 대장 카드(C26)와 인터뷰 질문지가 된다.
- **`(확인)` 0%는 정상이다.** 회사 자료가 없으면 0%가 맞다. 그렇다고 `[산업]`을 `[확인]`으로 올리면 안 된다.

## 8. 새 산업 시작 체크리스트

```
□ packs/_template/ 을 packs/{팩id}/ 로 복사
□ pack.json 의 id·industry·positions·fields 를 채운다
□ 원자료를 모은다 (§4 최소 구성)
□ 교정 사전을 만든다 (01-source-note.md §교정 사전 만드는 법)
□ P1 × 소스 수 → knowledge/소스노트/
□ 2편째에 헤딩 대조: for f in *.md; do grep -n "^## " "$f"; done
□ G1 통과 확인 (편마다)
□ P2 × 8회 → knowledge/00~07
□ G2 통과 확인
□ P4 1회 → field-matrix.json
□ G3 통과 확인. thin:true 가 있으면 소스 보강 후 재실행
□ P3 → cards.json
□ G4 검증 스크립트 실행
□ pack.json 의 sources·date_range·known_limits·last_updated 채운다
□ packs/README.md 현황표 갱신
```

## 9. 갱신 주기

| 대상 | 주기 |
|---|---|
| 시황·전망 | 6개월 지나면 회색 처리, 12개월이면 재검증 |
| 구조 (BM·용어·거래관행) | 규제 변경이나 사업재편이 있을 때만 |
| 카드 | 마스터가 바뀐 부분에 걸리는 카드만 재생성. 전체 재생성은 링크 그래프를 다시 깨뜨린다 |
| 매트릭스 | 밸류체인 위치 옵션이 늘어날 때 (예: 조선업에 해운사 트랙 추가) |

# P3 — 통합 마스터 → 카드 26장 (cards.json)

| 항목 | 내용 |
|---|---|
| 입력 | P2 산출 마스터 1권 + 분책 7권, P4 산출 `field-matrix.json` |
| 출력 | `packs/{{팩id}}/cards.json` — 카드 24~26장 |
| 산출 단위 | 산업당 1개 |
| 이전 단계 | [02-merge-pack.md](02-merge-pack.md) → [04-field-matrix.md](04-field-matrix.md) |
| 규격 근거 | `설계_감사투입전_온보딩도구_v1.md` §2(게이트), §6(매트릭스), §11-2(카드 규격) |
| 검증 기준 | `packs/shipbuilding/cards.json` (26장, 검수 완료) |

**이 프롬프트는 파이프라인에서 가장 중요하다.** 앞 두 단계는 정보를 잃지 않는 것이 목표였고, 여기서 처음으로 **버린다.** 무엇을 버리느냐를 정하는 것이 게이트이고, 게이트를 통과한 것만 카드가 된다.

**매트릭스를 먼저 만들고 이 단계로 온다.** 매트릭스가 없으면 무엇을 깊게 쓸지 정할 근거가 없어 산업 백과사전이 된다.

---

## 1. 카드 규격

| 항목 | 규격 | 이유 |
|---|---|---|
| 본문 | **800~1,400자** (태그 제외 순수 텍스트, 3~5분) | 한 번에 소화 가능한 최대치 |
| 표 | **최대 1개, 헤더 제외 6행 이하** | 표가 두 개면 이미 두 카드다 |
| 용어 미니사전 | 그 카드에 처음 나온 것 **2~4개, 한 줄 정의만** | 배경 설명은 다른 카드로 |
| 마무리 | **"이걸 알면 무엇이 달라지나" 1문장 필수** | 없으면 그 카드는 게이트를 잘못 통과한 것 |
| 다음 제안 | **3~5개, 자연어 질문 형태** | "3-2절 참조"가 아니라 "그럼 대금은 언제 받나요?" |
| 축 배지 | `산업` / `혼합` / `미확인` | 산업 일반론이 회사 사실로 읽히는 것을 화면에서 막는다 |
| 리드 | 1문장. 카드를 열기 전에 보이는 한 줄 | |

**다음 제안을 목차 항목이 아니라 질문으로 쓰는 것이 중요하다.** 목차는 읽어야 할 의무처럼 느껴지고 질문은 궁금증처럼 느껴진다. 진행 여부를 사용자가 고르게 하는 것이 이 설계의 목적이다.

**규격 예외 2가지** (이것만 허용, 카드에 사유를 명시한다)
- **들릴 말 사전 카드**: 용어 20개 내외의 목록이므로 표 행 수 제한을 적용하지 않는다. 대신 본문 산문을 최소로 한다.
- **미확인 대장 카드**: 표 2개(최상단 항목 / 그다음 항목)까지 허용한다.

## 2. 지식 게이트 — 카드로 만들지 말지 결정하는 5문

마스터에 있는 개념을 전부 나열하고 각각에 아래 5문을 던진다.

| # | 판정 질문 | Yes일 때 카드에 붙는 것 |
|---|---|---|
| Q1 | 이 개념을 알면 **계정잔액이 왜 발생했는지** 설명할 수 있는가? | 계정 연결 |
| Q2 | **권리와 의무가 누구에게, 언제** 발생하는지 달라지는가? | 기간귀속·권리와의무 |
| Q3 | 확인해야 할 **계약서·증빙·시스템**이 달라지는가? | 필요 자료 |
| Q4 | **금액·기간귀속·분류·평가**가 잘못될 가능성을 새로 발견할 수 있는가? | 감사위험 |
| Q5 | 회사에 **물어봐야 할 질문**이 달라지는가? | 인터뷰 질문 |

판정:
- **2개 이상 Yes, 또는 Q4가 Yes** → 카드로 만든다
- **1개 Yes 또는 특정 조건에서만 Yes** → 조건부. 조건을 명시하고, 독립 카드가 아니라 다른 카드의 한 문단으로 넣는다
- **전부 No** → **카드로 만들지 않는다.** 다만 인터뷰에서 들릴 말이면 **들릴 말 사전 카드에 한 줄 정의로만** 넣는다

전부 No인데 담당자가 회의에서 쓸 확률이 높은 말 — 이것이 소통 지식이다. 배경·역사·기술 원리는 싣지 않는다. **한 줄 정의만.** 조선업에서 선박 공학적 세부사양이 여기에 해당한다. 못 알아들으면 대화가 끊기지만, 감사절차를 바꾸지는 않는다.

**"이걸 알면 무엇이 달라지나"를 쓸 수 없으면 그 카드는 게이트를 잘못 통과한 것이다.** 쓰다가 막히면 카드를 지워라.

## 3. 트랙 구성과 카드 수

| 트랙 | 권장 장수 | 무엇이 들어가나 |
|---|---|---|
| `산업기초` | 5~6 | 판의 구성, 밸류체인, 참여자 관계, 제품 분류, 사이클, 규제 |
| `비즈니스` | 3 | 이익 공식, 가격 결정, 원가 핵심 항목 |
| `거래구조` | 8~9 | 계약부터 대금까지. **가장 두꺼운 트랙이어야 한다** |
| `기자재` (밸류체인·기자재) | 2 | 후방 단계 사업자의 시각. 감사대상이 그쪽일 때 필요 |
| `용어` | 1 | 들릴 말 사전 |
| `필드` | 4 | 매출·채권 / 매입·재고·원가 / 자금·금융상품 / 충당·우발 |
| `마무리` | 1 | 회사에 물어볼 것 — 미확인 대장 |
| **합계** | **24~26** | |

거래구조가 산업기초보다 얇으면 그 팩은 산업 소개 자료지 감사 온보딩 도구가 아니다.

산업에 따라 `기자재` 트랙 이름은 바뀐다(반도체면 소부장, 원전이면 기자재·시공). 트랙 **이름**은 산업에 맞춰 바꾸되 **역할**은 유지한다: "감사대상이 전방이 아니라 후방일 때 필요한 것".

## 4. 반드시 들어가야 하는 카드 유형 15가지

산업이 무엇이든 아래 15개는 반드시 있어야 한다. 산업 표현으로 갈아입되 역할은 같다. 카드가 없으면 그 팩은 미완성이다.

| # | 유형 | 무엇을 답하는 카드인가 | 조선업 대응 |
|---|---|---|---|
| 1 | **산업 90초** | 누가 누구에게 무엇을 파는 판인가. 첫 화면 | C01 |
| 2 | **밸류체인 위치** | 감사대상이 이 사슬 어디에 있고, 위치가 다르면 뭐가 달라지나 | C02 |
| 3 | **이익 공식** | 매출 = 무엇 × 무엇 − 무엇. 숫자의 크기를 예측하게 하는 골격 | C05 |
| 4 | **가격 결정** | 단가가 무엇으로 정해지나. 고정가인가 연동가인가 | C06 |
| 5 | **거래 흐름 단계** | 계약부터 인도까지 물리적으로 무슨 일이 순서대로 일어나나 | C08 |
| 6 | **대금 수취 구조** | 돈이 언제 얼마씩 들어오나. 마일스톤 표 | C09 |
| 7 | **대금표는 수익인식이 아니다** ★ | 현금 유입 일정과 수익인식 일정이 다르다는 것, 그 차이가 계약자산·계약부채로 남는다는 것 | C11 |
| 8 | **계약 변경·지연** | 계약이 도중에 바뀌거나 늦으면 금액·납기가 어떻게 조정되나 | C13 |
| 9 | **추정이 개입하는 지점** | 경영진 판단이 들어가는 곳은 어디인가 | C14 |
| 10 | **단계별 매출 도착 시차** | 전방이 좋다는데 이 회사 실적은 왜 아직인가 | C15 |
| 11 | **고객 집중** | 매출이 소수 고객에 몰리는 구조인가. 신용위험이 구조적인가 | C16 |
| 12 | **과거 크게 틀렸던 사례** | 이 산업이 실제로 크게 어긋났던 국면과 그때 재무제표에 난 일 | C20 |
| 13 | **들릴 말 사전** | 게이트 탈락했지만 회의에서 들릴 말 20개 내외 | C21 |
| 14 | **필드별 카드 ×4** | 매출·채권 / 매입·재고·원가 / 자금·금융상품 / 충당·우발 | C22~C25 |
| 15 | **회사에 물어볼 것 (미확인 대장)** | 산업 자료로 끝내 안 열린 것과 채우는 경로·첫 질문 | C26 |

7번이 이 팩 전체에서 가장 중요한 카드다. 업계 사람도 대금표와 수익인식을 섞어 말하고, 산업 강의 화자가 그렇게 설명하는 장면이 실제로 있다. 이 카드가 없으면 감사인이 그 오류를 그대로 물려받는다.

15번은 **산업 자료로 답할 수 없는 것을 정직하게 적는 카드**다. 없는 답을 지어내지 않는다는 원칙이 화면에 드러나는 자리다.

## 5. 축 태깅

| 값 | 언제 붙이나 |
|---|---|
| `산업` | 카드 전체가 산업 일반론. 회사 사실이 한 줄도 없다 |
| `혼합` | 산업 일반론 위에 "이건 회사 확인이 필요하다"가 함께 있는 카드 |
| `미확인` | 카드 전체가 아직 모르는 것의 목록 |

**산업 일반론을 회사 사실로 서술하는 것을 절대 금지한다.** "이 회사는 헤비테일입니다"는 회사 자료로 확인되기 전까지 쓸 수 없다. 산업팩 층에는 회사 사실이 한 줄도 들어가지 않는다.

# 역할

너는 회계법인 감사팀의 온보딩 담당이다. 산업 이해 마스터를 읽고, 곧 현장에 나가는 감사인이 **한 장씩 넘겨보며 산업을 잡을 수 있는 카드 24~26장**을 만든다.

**너는 산업을 가르치는 사람이 아니다.** 산업지식은 감사절차로 연결되기 위한 수단이며, 연결되지 않는 지식은 카드로 만들지 않는다.

# 작업 절차

## 1단계 — 게이트 판정 (내부, 출력하지 않음)

마스터의 개념을 전부 나열하고 각각에 5문을 적용하라.

Q1 계정잔액 설명 / Q2 권리·의무 귀속 / Q3 확인할 계약서·증빙·시스템 / Q4 금액·기간귀속·분류·평가 오류 / Q5 회사에 물을 질문

- 2개 이상 Yes 또는 Q4 Yes → **카드 후보**
- 1개 Yes 또는 조건부 → **조건 명시 후 다른 카드의 한 문단으로**
- 전부 No → **카드로 만들지 않는다.** 담당자가 회의에서 쓸 말이면 들릴 말 사전에 **한 줄 정의로만** 넣는다

매트릭스에서 `필수` 판정이 많은 개념일수록 두껍게, `조건부`는 얇게, `불필요`는 들릴 말 사전으로 보낸다.

## 2단계 — 카드 배치

§트랙 구성표대로 24~26장을 배치하고, §필수 카드 유형 15가지가 전부 커버되는지 대조한다. **빠진 유형이 있으면 다른 카드를 줄여서라도 넣는다.**

## 3단계 — 링크 그래프 설계

- 첫 카드는 항상 **산업 90초**, 둘째는 **밸류체인 위치**
- 카드마다 `next` 3~5개. 전부 **자연어 질문**
- **유입 링크가 0인 카드가 있으면 안 된다.** 그 카드는 도달 불가능하다
- 필드 카드에는 다른 필드 카드로 가는 링크를 넣지 않는다. 대신 마무리 카드로 보낸다
- 링크는 궁금증의 자연스러운 순서를 따른다. "그럼 대금은 언제 받나요?" → 대금 카드

## 4단계 — 집필

카드 하나를 쓸 때:

1. **본문 800~1,400자.** 태그를 제외한 순수 텍스트 기준. 세거나 재라
2. **표는 최대 1개, 헤더 제외 6행 이하** (들릴 말 사전·미확인 대장만 예외)
3. **용어 2~4개**, 한 줄 정의만. 그 카드에 처음 나온 것만
4. **`audit` 필드에 "이걸 알면 무엇이 달라지나" 1문장.** 못 쓰겠으면 카드를 지워라
5. **`lead`는 1문장.** 카드를 열기 전에 보이는 낚싯줄
6. 문체는 담백한 평서문. 설명하려 애쓰지 말고 사실을 놓아라
7. 원문에 있는 **비유를 살려라.** 산업을 모르는 사람에게는 비유가 본문보다 오래 남는다
8. 수치는 마스터에 있는 것만, 원문 단위 그대로, **"언제 기준"을 붙여서**
9. 상충하는 수치가 있으면 하나를 고르지 말고 "기준이 달라 섞어 쓰면 안 된다"고 적어라

## 5단계 — 자기검증

아래 검증을 전부 통과할 때까지 고쳐라. 검증 결과는 출력하지 말고 JSON만 출력한다.

- id 유일. `C01`부터 연번
- 모든 `next[].to`가 실제 존재하는 id
- 유입 링크 0인 카드 없음 (첫 카드 제외)
- 본문 글자 수 800~1,400 (태그 제외)
- 표 개수·행 수 규격 준수 (선언된 예외만 초과)
- `terms` 2~4개 (들릴 말 사전 카드는 0 허용)
- `next` 3~5개, 전부 물음표로 끝나거나 질문형
- `audit` 전 카드 존재
- 필수 카드 유형 15가지 전부 커버
- 허용 태그 외 사용 0, class·style 속성 0, 이모지 0
- 마스터에 없는 수치 0

```json
    "audit": "이걸 알면 무엇이 달라지나 — 한 문장",
    "terms": [
      { "t": "용어", "d": "한 줄 정의" }
    ],
    "next": [
      { "q": "자연어 질문", "to": "C06" }
    ]
  }
]
```

| 필드 | 타입 | 제약 |
|---|---|---|
| `id` | string | `C` + 2자리 연번. 유일 |
| `track` | string | 위 7개 중 하나 |
| `title` | string | 40자 이하 |
| `minutes` | number | 3~5. 본문 길이에 맞춰 |
| `lead` | string | 1문장 |
| `axis` | string | `산업` \| `혼합` \| `미확인` |
| `body` | string | HTML. 태그 제외 800~1,400자 |
| `audit` | string | 1문장. 필수 |
| `terms` | array | 2~4개. `t`=용어, `d`=한 줄 정의 |
| `next` | array | 3~5개. `q`=자연어 질문, `to`=대상 id |

# HTML 제약

허용 태그: `p` `ul` `ol` `li` `b` `em` `table` `tr` `th` `td` `blockquote` `br`
그 외 태그 금지. **`class`·`style` 속성 금지.** 표는 `<table><tr><th>…</th></tr><tr><td>…</td></tr></table>` 형태로만.

# 금지

- ❌ **자료에 없는 수치 생성.** 마스터에 없는 숫자는 한 개도 쓰지 않는다
- ❌ **회사 사실 단정.** "이 회사는 …입니다"는 회사 자료로 확인되기 전까지 금지. 산업 일반론을 회사 프로세스로 쓰는 것이 이 도구가 막아야 할 가장 위험한 실패다
- ❌ 이모지
- ❌ 허용 외 HTML 태그, class·style 속성
- ❌ 연결 사슬이 안 붙는 지식 게재 ("이걸 알면 무엇이 달라지나"를 못 쓰는 카드)
- ❌ 일반적인 감사위험 나열 — 이 산업 거래구조에 연결되지 않은 위험은 무의미하다
- ❌ 모르는 것을 그럴듯하게 채우기. **(미확인)이 정답이다**
- ❌ 800자 미만의 얇은 카드로 장수 채우기

# 출력

JSON 배열만 출력한다.

## 6. 톤 예시 — 조선업 결과에서 3장

새 산업의 카드를 쓸 때 문체와 밀도의 기준으로 삼는다. 전문은 `packs/shipbuilding/cards.json`.

### 예시 1 — 대금 수취 구조 (필수 유형 6번)

표를 쓰는 방식, 비유를 살리는 방식, 마지막에 다음 카드로 넘기는 방식을 본다.

```json
{
  "id": "C09",
  "track": "거래구조",
  "title": "대금은 언제 받나 — 5단계",
  "minutes": 3,
```

### 예시 2 — 대금표는 수익인식이 아니다 (필수 유형 7번)

산업 자료의 오류를 정정하고, 산업 자료로 못 채우는 것을 정직하게 선언하는 카드다.

> 이 도구에서 가장 중요한 카드다. **대금을 받는 일정과 매출을 인식하는 일정은 서로 다른 것이다.**
>
> (…) 어긋난 차이는 재무상태표에 잔액으로 남는다. 인식한 매출이 청구액보다 많으면 **계약자산(미청구공사)**, 받은 돈이 인식한 매출보다 많으면 **계약부채(초과청구공사)**다. 대금이 뒤로 몰린 헤비테일 구조에서는 일은 했는데 청구를 못 한 금액, 즉 계약자산이 크게 쌓이는 형태가 된다. (…) **대금 구조를 알면 잔액의 모양이 예측된다.**
>
> 주의할 것은 업계 사람도 이 둘을 섞어 말한다는 점이다. 실제로 산업 강의에서 화자가 대금표를 가리키며 그것이 조선의 매출 인식이라고 설명하는 장면이 있다. 부정확한 표현이다. 인터뷰에서 담당자가 대금표를 내밀며 우리 매출 인식 스케줄이라고 말하면, 그것은 대금표다.
>
> 그리고 **산업 자료 어디에도 조선사가 어떤 방법으로 수익을 인식하는지, 진행률을 무엇으로 산정하는지는 한 번도 나오지 않는다.** 산업 지식으로 채울 수 없는 항목이고, 회사의 수익인식 회계정책 주석과 핵심감사사항, 담당자 확인으로만 채워진다.

`lead`: "담당자가 대금표를 내밀며 '이게 저희 매출 인식입니다'라고 말할 것이다. 그것은 대금표다."

### 예시 3 — 미확인 대장 (필수 유형 15번)

산업 자료가 답을 못 주는 지점을 표로 세우고, 각 항목에 **어디서 채우나 / 첫 질문**을 붙인다. 이 카드만 표 2개가 허용된다.

> 여기까지가 산업 자료로 갈 수 있는 끝이다. 아래 항목은 강의 8편을 전부 합쳐도 채워지지 않았다. **강의를 더 봐도 열리지 않는다. 사업보고서 주석과 KAM, 그리고 담당자 인터뷰로만 열린다.**

| 미확인 항목 | 어디서 채우나 | 첫 질문 |
|---|---|---|
| 수익인식 방법과 진행률 산정 방식 | 주석의 수익인식 회계정책, KAM, 회계팀 | 기간에 걸쳐인가요 한 시점인가요. 진행률은 원가투입법인가요 공정률인가요 |
| 체인지오더 처리 — 8편 전체 언급 0회 | 공무·원가 인터뷰, 계약서 | 승인 전 체인지오더를 매출에 반영하시나요. 기준이 뭔가요 |

> 순서가 중요하다. 주석과 KAM을 먼저 닫고 들어가야 인터뷰에서 남은 질문이 진짜 질문이 된다. 그리고 담당자의 답이 산업 일반론과 다르면, 그 **불일치가 이 준비의 가장 값진 산출물**이다.

## 7. 출력 후 검증

`cards.json`을 저장한 뒤 반드시 돌린다.

```python
import json, re, collections
cards = json.load(open("packs/{팩id}/cards.json"))
ids = [c["id"] for c in cards]

assert len(ids) == len(set(ids)), "id 중복"
assert 24 <= len(cards) <= 26, f"장수 {len(cards)}"

inbound = collections.Counter()
for c in cards:
    for n in c["next"]:
        assert n["to"] in ids, f"끊긴 링크 {c['id']} -> {n['to']}"
        inbound[n["to"]] += 1
orphans = [i for i in ids[1:] if inbound[i] == 0]
assert not orphans, f"유입 0: {orphans}"

ALLOWED = {"p","ul","ol","li","b","em","table","tr","th","td","blockquote","br"}
for c in cards:
    body = c["body"]
    text = re.sub(r"<[^>]+>", "", body)
    assert 800 <= len(text) <= 1400, f"{c['id']} 본문 {len(text)}자"
    tags = {t.lstrip("/") for t in re.findall(r"<(/?\w+)[ >]", body)}
    assert tags <= ALLOWED, f"{c['id']} 허용 외 태그 {tags - ALLOWED}"
    assert not re.search(r"<\w+\s+(class|style)=", body), f"{c['id']} 속성 위반"
    assert c["axis"] in {"산업", "혼합", "미확인"}, f"{c['id']} axis"
    assert c.get("audit"), f"{c['id']} audit 없음"
    assert 3 <= len(c["next"]) <= 5, f"{c['id']} next {len(c['next'])}"
    if c["track"] != "용어":
        assert 2 <= len(c["terms"]) <= 4, f"{c['id']} terms {len(c['terms'])}"
    if c["track"] not in ("용어", "마무리"):
        tabs = re.findall(r"<table>.*?</table>", body, re.S)
        assert len(tabs) <= 1, f"{c['id']} 표 {len(tabs)}개"
        for t in tabs:
            assert t.count("<tr>") - 1 <= 6, f"{c['id']} 표 {t.count('<tr>') - 1}행"

print(f"통과 {len(cards)}장", collections.Counter(c["track"] for c in cards))
```

기계로 못 잡는 것은 사람이 본다.

- 수치 전부가 마스터에 실재하는가 (전수 대조)
- 회사 사실을 단정한 문장이 있는가
- 필수 카드 유형 15가지가 전부 있는가
- `audit` 문장이 진짜로 "무엇이 달라지는지"를 말하는가, 요약을 반복하는 것은 아닌가
